所有模型的固定推論 YAML 均預設 BF16、`generate_positions=false`，且列有可選 diffusion checkpoint；Beatforge 將繼續停用非受管理的外部 checkpoint。V30 與 V31 的模型架構／tokenizer 不同於 V32，不能直接套用 V32 專屬 backbone shim 或 fast decoder 修正。新 worker 必須以模型 ID 選對 config 和相容處理，並在支援 GPU 上實測 BF16／FP32 fallback、記憶體與輸出。

## 可擴充目錄契約與上架門檻

- 每筆模型有不可重用的 package ID、官方 repository、不可變 revision、standard 子路徑、逐檔大小／SHA-256、授權證據、訓練／推論 config 雜湊、能力標記、取得方式與驗收狀態。`research_only` 表示尚未通過生成驗收；0.3-02 已提供套件安裝與驗證，但不代表模型可供生成。V30／V31 只接受使用者手動匯入固定版本，V32-mini／V32 可由應用程式從上游下載。日後加入模型須透過應用程式更新，不在執行時追蹤 `main`。
- 能力標記至少區分「已實測支援」、「訓練設定具備但未實測」、「不具備／停用」。對不具備的功能，生成頁在送出前停用或拒絕，worker 也要再次拒絕；不得只把值寫進 `.osu` 就宣稱模型受到該條件控制。
- 上架前需完成授權審查、實際下載 SHA-256、離線載入與 health、每模型單／多難度生成、reference 與各欄位契約、validation、osu! 匯入、取消／retry、GPU 資源紀錄及 V32 回歸。舊任務保留原模型 ID／版本，缺模型時不自動替換。

## 待確認事項與發布決策

1. **V30、V31 權重授權未明，需記錄發布決策。** 官方模型卡沒有可用授權聲明；上游原始碼的 MIT 不應直接推論為權重授權。Beatforge 無法自行替權重補授權。0.3.0 規畫讓使用者自行在瀏覽器取得權重，再以固定雜湊手動匯入；Beatforge 不提供這兩個模型的下載或權重鏡像。這可避免 Beatforge 散布權重，卻不等於上游使用條款已釐清。正式開放匯入前仍須記錄此界線與發布決策；目前維持 `research_only`。
2. **V30、V31 部分 UI 條件無模型訓練訊號。** 尤其 V30 描述詞、V30／V31 目標星數；3-03～3-05 必須訂清輸入策略與提示，不能沿用 V32 文案。
3. **模型執行相容尚未驗收。** 本階段沒有下載大型權重或執行 GPU 推論。V31／V30 的 backbone、現有 TIMING reference、V32-mini 的低顯存表現，以及各模型的預設欄位輸出都需在 3-04／3-09 實測。
