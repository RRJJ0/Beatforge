# 0.2.0 欄位契約（實作基準）

[English](v0.2.0-field-contract.md) · [開發規劃](v0.2.0-plan.zh-TW.md) · [生成頁線框](../ui/beatforge-v020-generate.drawio)

狀態：設計決議，尚未實作；實機生成與匯入仍須驗收。0.2.0 線框已經使用者確認。以下數值範圍是 **Beatforge 的輸入限制**，不是 osu! 官方對所有譜面的限制；線框上的數值只代表示例。

## 依據與現況

- [osu! `.osu` 格式](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_(file_format))定義 `[Metadata]` 的 `Creator`、`TitleUnicode`、`ArtistUnicode`、`Source`、以空白分隔的 `Tags`，以及 `[Difficulty]` 的 HP／OD（0–10）、`SliderMultiplier`、`SliderTickRate`。後兩者在格式文件沒有上限。
- 固定的 [Mapperatorinator `inference.py` 原始版本](https://github.com/OliBomby/Mapperatorinator/blob/0e2b0e387aab4b35c64b0b11b12d47578dea7587/inference.py) 已把 HP、OD、滑條速度與滑條點倍率同時傳入 `GenerationConfig` 與 `BeatmapConfig`。無參考譜面且未填時，上游預設依序為 `5`、`8`、`1.4`、`1`；有參考譜面時，空值會先繼承參考譜面的設定。這是程式路徑的結論，仍需以固定 V32 實際生成驗證。
- 現行 worker 將 `Creator` 固定為 `Beatforge AI`，`TitleUnicode`／`ArtistUnicode` 複製一般欄位，公開 `Tags` 固定為 `Beatforge AI mapperatorinator`。新契約不得把上游自動生成的模型參數標籤公開。

## 要求與輸出

JSON 欄位採現有 camelCase 慣例。選用文字使用 `null` 或缺欄，不把空白字串當作有意義的值；傳入前先 trim。所有文字拒絕換行、控制字元與破壞 `.osu` key/value 結構的內容；新單行欄位至多 200 個 Unicode 字元。

| 範圍／JSON 欄位 | 空值時的有效值 | 明確輸入 | `.osu` 輸出 |
| --- | --- | --- | --- |
| 共用 `creator` | `Beatforge AI` | 1–200 字元；僅填實際譜師，不自動宣稱使用者製譜 | `[Metadata] Creator` |
| 共用 `titleUnicode` | 已驗證的 `title` | 1–200 字元 | `TitleUnicode` |
| 共用 `artistUnicode` | 已驗證的 `artist` | 1–200 字元 | `ArtistUnicode` |
| 共用 `source` | 空字串，不繼承參考譜面 | 1–200 字元 | `Source` |
| 共用 `tags` | 無使用者標籤 | 最多 16 個、每個 1–64 字元；每個標籤不含空白、控制字元、冒號、等號或方括號；大小寫不敏感去重 | `Tags`：使用者標籤後併入不可移除的 `Beatforge AI mapperatorinator`，以單一空白連接並去重 |
| 每難度 `hpDrainRate` | 無參考譜面 `5`；有參考譜面繼承其值 | 有限數字 `0–10` | `[Difficulty] HPDrainRate` |
| 每難度 `overallDifficulty` | 無參考譜面 `8`；有參考譜面繼承其值 | 有限數字 `0–10` | `OverallDifficulty` |
| 每難度 `sliderMultiplier` | 無參考譜面 `1.4`；有參考譜面繼承其值 | 有限數字 `0.1–10` | `SliderMultiplier` |
| 每難度 `sliderTickRate` | 無參考譜面 `1`；有參考譜面繼承其值 | 有限數字 `0.1–10` | `SliderTickRate` |

滑條兩欄的 `0.1–10` 是本版保守且有限的產品界線；Rust 目前只檢查產物大於零。前端、Rust 與 worker 要採同一契約，不能由某一層悄悄截斷或改用 UI 示例值。UI 的「未設定」須與明確輸入數值區分；參考譜面可用時，旁邊提示會繼承。

## 套用時機與相容

共用 metadata 在每難度的上游 `compile_args` **之前**明確設定；`source` 即使空白也要指定為 `""`，避免繼承參考譜面。每難度數值同樣在 `compile_args` 之前傳入，上游可同時用於生成條件和輸出檔案。不得只在生成後替換 `SliderMultiplier`：osu! 的[滑條時長計算](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_(file_format)#sliders)會因此改變。UI 應寫「生成設定／產出譜面的基礎值」，不保證實際星數或滑條品質。

舊 `request_json` 已存於 `jobs` 表，重試與重新生成會重讀該 JSON。新欄位使用 serde 預設 `None`／空列表；**舊任務**要保留 0.1.0 固定 Creator、Unicode 與公開 Tags 行為，且不得吃到新版 UI 預設。這可以由缺少新欄位辨識，不需要 SQLite 欄位遷移；新任務則儲存完整原始要求與明確欄位。無法以舊版 app 讀取新任務或回退 worker 不在本版保證範圍，更新與復原仍依既有備份流程。

worker 協定新增欄位時升至 v2，讓舊 worker 明確拒絕新命令；Rust 與 Python 同步更新。provenance 使用 schema v2，逐難度記錄「要求值（含 null）／套用值／來源（明確、參考譜面、上游預設）」及固定來源版本；schema v1 歷史紀錄仍可讀。公開 `.osu` metadata 不得包含提示詞、seed、本機路徑或模型路徑。重試前先驗證保存的要求；若目前固定版本無法重現，明確報錯，不默默改值。

## 實作驗收焦點

- 無參考譜面、有參考譜面、明確輸入與空值各產一個單難度案例；比對 request、provenance 和 `.osu` 的值。
- 多難度交錯設定與部分失敗時，逐檔確認設定未串用；`Tags` 只出現公開詞彙且保留 AI 揭露。
- 對滑條速度的非預設值以實機生成與 osu! 匯入確認時長及結構；若測試不通過，不只改 `.osu` 欄位來湊數值，須回修契約或縮小本版範圍。

實機紀錄（2026-11-03）：無參考譜面的 `BF-1793709680360-0` 使用滑條速度 `1.6`、滑條點倍率 `1.5`；request、provenance 與 `.osu` 一致，439 條滑條的計算時長均為正且有限，使用者回報 osu! 試玩正常。此結果只驗證該組數值。

參考譜面實機紀錄（2026-11-03）：`BF-1793715820475-3` 成功載入同歌曲的 AI 5s `.osu`。參考譜面與產出 `.osu` 的 HP／OD／滑條速度／滑條點倍率皆為 `5`／`8`／`1.6`／`1.5`，但任務 request 四欄均明確填入這些數值，provenance 來源也均為 `explicit`。因此本例驗證了「有參考譜面且明確輸入」的傳遞，尚未驗證四欄留空時的參考譜面繼承。validation 無錯誤，記錄 6 個物件越界警告及 6 項非破壞性格式修復；osu! 試玩結果尚未提供。

空值繼承實機紀錄（2026-11-03）：`BF-1793716316106-4` 的 request 將四欄全部留為 `null`；worker 紀錄與 provenance 均指出從同歌曲參考譜面繼承 HP／OD／滑條速度／滑條點倍率 `5`／`8`／`1.6`／`1.5`，已驗證 `.osu` 四欄亦相同。validation 無錯誤，記錄 2 個物件越界警告及 6 項非破壞性格式修復；使用者回報在 osu! 試玩正常。此例的參考譜面空值繼承驗收完成。
