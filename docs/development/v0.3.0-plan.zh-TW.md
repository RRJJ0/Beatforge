# Beatforge 0.3.0 開發規劃（範圍草案）

[English](v0.3.0-plan.md) · [開發者文件](README.zh-TW.md) · [0.2.0 規劃](v0.2.0-plan.zh-TW.md)

狀態：已確認的版本方向，尚未實作或排定發布日期。0.3.0 以**多模型選擇與生成品質觀察**為主軸，保留 osu!standard 與現有本機生成、驗證、歷史及匯入流程。

## 版本範圍

### 1. 經驗收的多模型選擇

- 0.3.0 的目標清單為 **V30、V31、V32-mini、V32**；V32 維持預設。前三者各自確認相容性、檔案、來源 revision、授權、SHA-256、推論設定及實機表現後，才標示為正式支援。不得因某模型尚未驗收，就悄悄把它從承諾清單移除；若遇阻礙，記錄問題並在版本範圍決議中明確處理。
- 使用者可自由決定要下載哪些模型；每個模型可獨立下載、驗證、修復與移除。生成頁每個任務選擇**一個**已安裝且適用 osu!standard 的模型，顯示安裝狀態、支援功能及必要的硬體提示；不接受任意 checkpoint 路徑。
- 模型清單採可擴充的受管理目錄：日後新增上游模型時，可加入獨立 ID、鎖定來源、檔案清單、能力與驗收紀錄，不須重寫生成頁或任務資料格式；新增模型仍須經應用程式版本更新及驗收，不在執行時自動信任上游新版本。
- 任務 request、歷史、retry／重新生成及 provenance 記錄固定的模型 package ID、版本與實際來源。原模型缺失時提供安裝或明確錯誤，不靜默改用 V32。舊任務仍依原有 V32 語意讀取。
- 逐模型核對描述詞、負面描述詞、參考譜面、metadata、HP／OD／滑條設定、精度與預設值。不支援的組合在送出前阻擋或清楚說明；各模型的 worker 相容處理須隔離。

### 2. 同條件比較與品質提示

- 從歷史任務複製同一首歌、難度與有效設定，只更換模型建立新任務；兩筆輸出與 provenance 各自保留。結果比較至少呈現模型、耗時、驗證警告、物件數及按時間分布。
- 對長時間無新物件、異常密集的同時點物件提供可定位時間區間的警告。以 0.2.0 已知的約 20 秒空段作調查案例，比較同歌曲、同難度在四個模型的原始及驗證後輸出。此分析僅輔助人工檢查，不自動改寫遊玩內容，也不把結構驗證等同品質審核。

### 3. 移除無效的「圖譜輸出資料夾」設定

- 從設定畫面移除 **Beatmap output folder／圖譜輸出資料夾** 的輸入與 Browse、重設選項；更新雙語標題與說明，明確指出成品保存在應用程式管理的 `jobs/<job-id>/validated/`，可從任務／歷史開啟。暫存資料夾與 osu! 安裝路徑仍各自顯示。
- 從新設定的前後端型別、儲存、匯出／匯入及診斷資料中移除 `outputPath`。舊版已儲存的設定與匯出 JSON 若帶有該欄位，升級／匯入時安全忽略；不因舊欄位而阻擋其他設定，亦不把舊路徑當作實際產物位置。
- 既有 `jobs` 成果及歷史紀錄保持可用。舊 `outputs` 目錄若已存在，不因設定遷移自動刪除；清楚區分 `AppPaths.outputs` 的舊目錄與 worker 的實際輸出路徑，確認沒有其他流程依賴後再移除不必要的目錄建立或 API 欄位。

## 驗收條件

1. V30、V31、V32-mini、V32 均可按需獨立安裝，並在支援的 Windows／NVIDIA 硬體完成模型載入、單難度與多難度生成、驗證、osu! 匯入及重試；GPU-free 契約測試覆蓋模型缺失、損壞、版本不符與舊任務讀取。
2. 同歌曲、同難度可建立不同模型的獨立任務並比較結果；已知空段能被標出供人工檢查。記錄各模型的警告、耗時與顯存，不預設某模型品質較好。
3. 更改或匯入舊 `outputPath` 不改變新任務產物位置；任務／歷史的「開啟成品」定位至實際 `jobs` 成果。舊設定與既有成果升級後仍可讀，設定匯出不再含無效欄位。
4. 更新中英文使用說明、模型相容矩陣、第三方聲明與發布測試；正式發布仍依候選版手冊驗收安裝與更新路徑。

## 本版不包含

LoRA、任意使用者 checkpoint、taiko／catch／mania、AMD／Linux、遠端 worker，以及自動修正譜面品質。V30／V31／V32-mini／V32 以外的新模型留待後續應用程式版本，在完成相容與實機驗收後加入。
