# 0.2.0 field contract (implementation baseline)

[繁體中文](v0.2.0-field-contract.zh-TW.md) · [Development plan](v0.2.0-plan.md) · [Generate wireframe](../ui/beatforge-v020-generate.drawio)

Status: design decision, not implemented; real generation and import still require acceptance. The user has approved the 0.2.0 wireframe. Numeric ranges below are **Beatforge input limits**, not universal limits imposed by osu!; wireframe values are examples.

## Basis and current behavior

- The [osu! `.osu` format](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_(file_format)) defines `Creator`, `TitleUnicode`, `ArtistUnicode`, `Source`, and space-separated `Tags` in `[Metadata]`, plus HP/OD (0–10), `SliderMultiplier`, and `SliderTickRate` in `[Difficulty]`. The format page gives no upper bound for the latter two.
- The pinned [Mapperatorinator `inference.py`](https://github.com/OliBomby/Mapperatorinator/blob/0e2b0e387aab4b35c64b0b11b12d47578dea7587/inference.py) passes HP, OD, slider multiplier, and tick rate to both `GenerationConfig` and `BeatmapConfig`. With no reference beatmap, omitted values default to `5`, `8`, `1.4`, and `1`, respectively; with a reference beatmap, missing values first inherit its settings. This is a source-code finding, pending real generation with pinned V32.
- The current worker fixes `Creator` to `Beatforge AI`, copies title/artist to their Unicode counterparts, and fixes public `Tags` to `Beatforge AI mapperatorinator`. The new contract must not expose upstream auto-generated model-parameter tags.

## Request and output

JSON names follow the existing camelCase convention. Optional text uses `null` or a missing key; whitespace-only input is not a meaningful value. Trim before passing values onward. All text rejects line breaks, control characters, and content that could break `.osu` key/value structure; new single-line fields are limited to 200 Unicode characters.

| Scope / JSON field | Effective value when omitted | Explicit input | `.osu` output |
| --- | --- | --- | --- |
| Shared `creator` | `Beatforge AI` | 1–200 characters; only name the actual mapper, never claim the user mapped the chart automatically | `[Metadata] Creator` |
| Shared `titleUnicode` | Validated `title` | 1–200 characters | `TitleUnicode` |
| Shared `artistUnicode` | Validated `artist` | 1–200 characters | `ArtistUnicode` |
| Shared `source` | Empty string; do not inherit the reference map | 1–200 characters | `Source` |
| Shared `tags` | No user tags | Up to 16 tags, each 1–64 characters without whitespace, controls, colon, equals sign, or brackets; deduplicate case-insensitively | `Tags`: user tags plus non-removable `Beatforge AI mapperatorinator`, joined with single spaces and deduplicated |
| Per difficulty `hpDrainRate` | `5` without a reference; otherwise inherit | Finite number `0–10` | `[Difficulty] HPDrainRate` |
| Per difficulty `overallDifficulty` | `8` without a reference; otherwise inherit | Finite number `0–10` | `OverallDifficulty` |
| Per difficulty `sliderMultiplier` | `1.4` without a reference; otherwise inherit | Finite number `0.1–10` | `SliderMultiplier` |
| Per difficulty `sliderTickRate` | `1` without a reference; otherwise inherit | Finite number `0.1–10` | `SliderTickRate` |

The `0.1–10` bounds for sliders are finite product guardrails for this release; current Rust output validation checks only that values are positive. Frontend, Rust, and worker must agree and must not silently clamp or substitute mockup values. The UI must distinguish “not set” from an explicit number and explain inheritance when a reference map is selected.

## Application timing and compatibility

Set shared metadata explicitly **before** upstream `compile_args` for each difficulty. Set `source` to `""` even when empty so it cannot inherit from a reference beatmap. Pass per-difficulty numbers before `compile_args` too; upstream can then use them for both generation conditioning and file output. Do not merely replace `SliderMultiplier` after generation: the [osu! slider-duration calculation](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_(file_format)#sliders) would change. UI language should say “generation setting / base value in output”, not promise a star rating or mapping quality.

The existing `jobs.request_json` stores inputs, and retry/regenerate reread that JSON. New fields should deserialize with `None`/empty-list defaults. **Legacy jobs** must keep 0.1.0 fixed Creator, Unicode, and public Tags behavior, and must never adopt new UI defaults. Missing new keys distinguish them without a SQLite column migration; new jobs store the complete original request with explicit fields. Reading new jobs in an older app or rolling back a worker is not guaranteed; existing backup/recovery guidance remains in force.

Bump the worker protocol to v2 with the new fields so an old worker rejects new commands explicitly; update Rust and Python together. Use provenance schema v2 to record, per difficulty, requested values (including null), applied values, and their origin (explicit/reference/upstream default), with pinned source versions; historical schema v1 remains readable. Public `.osu` metadata must exclude prompts, seeds, local paths, and model paths. Validate stored requests before retry; if current pinned components cannot reproduce one, fail clearly instead of silently changing values.

## Implementation acceptance focus

- Generate no-reference, reference, explicit, and omitted-value single-difficulty cases; compare request, provenance, and `.osu` values.
- For differing multi-difficulty settings and partial failures, inspect every output file for cross-contamination; `Tags` must contain only public terms and preserve AI disclosure.
- Generate a non-default slider multiplier on supported hardware and import it into osu! to check duration and structure. If this fails, revise the contract or narrow the release scope instead of editing the `.osu` header to merely match the number.
