Status: planning draft; no release date is set. This document describes proposed deliverables and acceptance. Implemented behavior, tests, and the final release notes determine what ships.

Generate screen [PNG preview](../ui/exports/16-generate-v020.png) · [editable draw.io wireframe](../ui/beatforge-v020-generate.drawio). The wireframe is approved; its values are examples. See the [field contract](v0.2.0-field-contract.md) for effective rules.

## Goal and scope

The proposed 0.2.0 focus is **osu!standard beatmap settings and song metadata**. Users should be able to enter common song information and set HP, OD, base slider velocity, and slider tick rate for each difficulty. Every generated `.osu` should reflect the accepted settings. The 0.1.0 Mapperatorinator V32, multi-difficulty, validation, and osu! import flow remain the foundation.

Version 0.1.0 already has title, artist, difficulty name, target star rating, AR, CS, and hitsound options. Proposed additions are:

| Level | Proposed fields | Output |
| --- | --- | --- |
| Shared song | Creator, original-script title/artist, source, public tags | `[Metadata]` in each difficulty's `.osu` |
| Per difficulty | HP, OD, base slider velocity, slider tick rate | `[Difficulty]` in the corresponding `.osu` |

“Public tags” means `.osu` `Tags`. Model assistance must still be disclosed according to the [sharing guidance](../user/sharing.md). Prompts, seeds, model paths, and local paths must not enter public metadata; they remain in managed job data and provenance.

Stack leniency, countdown, widescreen, and other osu! fields need a compatibility review and are not required deliverables for this version. Multiple models, LoRA, custom checkpoints, other game modes, AMD/Linux, and remote workers remain [longer-term ideas](roadmap.zh-TW.md#後續方向), outside 0.2.0 acceptance.

## Acceptance criteria

- UI, Rust, and worker reject invalid text, non-finite or out-of-range numbers, and unsupported fields with actionable errors; a rejected request leaves no partial job.
- Inspect `.osu` files from single- and multi-difficulty outputs: shared metadata matches, and each difficulty's settings match its accepted request. Omitted options preserve confirmed default behavior.
- Retry uses the stored request, without silently adopting changed UI defaults. Provenance distinguishes requested and effective values and identifies the model and worker versions.
- Output still passes structural, safety, and asset validation; preview and osu! import work. Mapping quality still requires human review.
- English and Traditional Chinese UI/docs stay aligned, the GPU-free release gate passes, and real single- and multi-difficulty generation is accepted on supported Windows/NVIDIA hardware.

## Decisions before implementation

- The [field contract](v0.2.0-field-contract.md) specifies defaults, ranges, and application timing. Real fixed-V32 generation and osu! import passed; non-default slider duration and reference inheritance still need separate checks.
- The rule for user-entered Creator alongside public AI tags is recorded; check that UI guidance and actual output agree before release.
- No SQLite migration is needed; the worker protocol is now v2 and provenance schema is v2. Legacy jobs remain readable; cross-version update and rollback boundaries need a 0.2.0 release candidate.
