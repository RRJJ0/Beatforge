## 目標與範圍

0.2.0 建議聚焦於 **osu!standard 譜面設定與歌曲 metadata**。使用者應能在建立任務時填寫常用的歌曲資訊，並為每個難度設定 HP、OD、基本滑條速度及滑條點倍率；產出的每張 `.osu` 應忠實反映已接受的設定。保留 0.1.0 的 Mapperatorinator V32、多難度、驗證與 osu! 匯入流程。

0.1.0 已有標題、歌手、每難度名稱、目標星數、AR、CS 與 hitsound 選項。預計新增：

| 層級 | 預計欄位 | 輸出位置 |
| --- | --- | --- |
| 歌曲共用 | 譜師、原文標題／歌手、來源、公開標籤 | 各難度 `.osu` 的 `[Metadata]` |
| 每個難度 | HP、OD、基本滑條速度、滑條點倍率 | 對應 `.osu` 的 `[Difficulty]` |

「公開標籤」指 `.osu` 的 `Tags`；模型使用揭露仍須遵循[分享與上傳說明](../user/sharing.zh-TW.md)。生成提示詞、seed、模型路徑和本機路徑不得寫入公開 metadata，仍留在受管理的任務與 provenance 中。

堆疊寬容度、倒數、寬螢幕及其他 osu! 欄位先做相容性評估，不列入本版必要交付。多模型、LoRA、自訂 checkpoint、其他模式、AMD／Linux 與遠端 worker 仍保留在[長期後續方向](roadmap.zh-TW.md#後續方向)，不作為 0.2.0 驗收條件。

## 細分子項目

依下列順序進行；核取方塊表示實際工作狀態。UI 線框已確認，工作包 A 的文件決議已記錄；實作與實機驗證尚未完成。

### 工作包 A：欄位契約與資料相容

- [x] 列出新欄位的型別、合法範圍、空值／預設行為和 `.osu` 欄位對應；核對 osu! 格式與固定 V32 能力。
- [x] 決定 HP、OD、滑條速度與滑條點倍率的推論前／生成後套用方式；在 UI 說清實際效果，不暗示未支援的模型控制。
- [x] 設計舊任務讀取／重試、設定儲存與 provenance 的相容方案；確定是否需要 schema 升級及回退界線。

### 工作包 B：生成頁 UI 與互動

進度：使用者已確認畫面驗收沒有明顯問題；預設難度名稱改為 `AI 4.8s` 格式。已完成可編輯的欄位預覽、雙語文案、欄位檢查與逐難度摘要；新欄位在工作包 C 接通前會阻止送出，避免靜默遺失。以下核取方塊待端到端可用與最小視窗技術驗收後勾選。

- [ ] 依線框實作歌曲共用欄位，保留現有音訊與選用素材流程；Creator 與公開標籤附近顯示必要的揭露提示。
- [ ] 在目前選取難度的進階設定加入 HP、OD、基本滑條速度與滑條點倍率；切換、新增、刪除難度時維持各自輸入。
- [ ] 提供欄位旁驗證、未填選項的明確表示、送出前的共用資料與逐難度摘要；長表單在 1080 × 700 最小視窗可捲動並可操作。
- [ ] 英文與繁中標籤、說明和錯誤訊息一致；鍵盤焦點、標籤關聯與數值單位可辨識。

### 工作包 C：Request、持久化與 worker

- [ ] 擴充 TypeScript request 與 Rust domain validation；只傳白名單欄位，對控制字元、換行、非有限數值與越界值拒絕建立任務。
- [ ] 儲存完整有效要求，讓佇列、重新啟動及 retry 使用同一組設定；舊版記錄沿用經確認的預設行為。
- [ ] 擴充 worker 命令及白名單驗證；將共用 metadata 與每難度數值寫入對應 `.osu`，部分難度失敗時不串用設定。
- [ ] provenance 記錄要求值與實際套用值，並維持私密參數不進入公開 `.osu` metadata。

### 工作包 D：驗證與發布

- [ ] 對單／多難度 `.osz` 逐檔驗證 metadata、數值、資產引用、封裝安全與輸出一致性；涵蓋空值、無效輸入、部分失敗與 retry。
- [ ] 確認預覽、osu! 匯入、舊任務讀取及升級復原；執行 GPU-free release gate 與支援硬體上的實際生成。
- [ ] 更新 worker 協定、使用指南、版本說明與已知限制，完成中英文對照及文件連結檢查。

## 驗收條件

- UI、Rust 與 worker 對無效文字、非有限數值、越界值或不受支援欄位給出明確錯誤；任務建立前不留下半成品。
- 單難度與多難度結果逐一檢查 `.osu`：歌曲共用欄位相同，每難度欄位與該難度的有效要求一致；未填的選項保留經確認的預設行為。
- 重試使用原任務記錄的設定，不因 UI 預設值或後續設定變化而無提示改變；provenance 能區分要求值、實際套用值及模型／worker 版本。
- 產物仍通過現有結構、安全與資產驗證，預覽及 osu! 匯入可用；生成品質仍需人工檢查。
- 中英文 UI／文件同步，GPU-free release gate 通過，並在支援的 Windows／NVIDIA 環境以實際單難度與多難度生成驗收。

## 發布前待決事項

- 欄位、預設與套用時機已由[欄位契約](v0.2.0-field-contract.zh-TW.md)決定；仍須以固定 V32 實機生成驗證滑條時長、參考譜面繼承及 osu! 匯入。
- 自訂譜師與公開 AI 標籤的並存規則已記錄；發布前確認 UI 提示與實際輸出相符。
- 任務資料不需 SQLite 遷移，worker 協定與 provenance 預定升級；舊版資料讀取與回退界線仍需測試。
